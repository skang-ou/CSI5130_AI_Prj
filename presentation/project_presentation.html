The testing problem

REQ-002: SOC falls below 10% while the vehicle is in Drive.

FieldSaved Zero-Shot output
GivenVehicle is in Drive and SOC is at or above 10%.
WhenSOC falls below 10%.
ThenDisplay a low-battery warning.

The test must retain the state guard and the threshold.

2

Dataset and generation workflow

DifficultyRequirementsExample
Easy10Threshold warnings
Medium10State guards and response deadlines
Hard10Debounce conditions and logical restrictions

Load requirement, build prompt, call the API, parse JSON, save output.

30 requirements × 3 strategies = 90 main outputs.

Synthetic data. Evaluation reference fields stay out of prompts.

3

Three prompting strategies

StrategyPrompt content
Zero-ShotTask and JSON format, without worked examples
StructuredSeven rules for states, triggers, logic and timing
Few-ShotFour independent demonstrations before the target task

Same requirement set, system instruction and output format.

Recorded model argument: gpt-5.6.

Few-Shot examples are separate from all 30 evaluation requirements.

4

Evaluation rubric

CriterionReview target
PreconditionsUsable initial state and required guards
TriggerConcrete event or elapsed condition
Expected behaviorRequired actions and response deadlines
Conditions / boundariesFidelity within the chosen scenario
Unsupported behaviorNo unjustified assumptions or responses

Each criterion: 0, 1 or 2. Equal-weight total: 0–10.

One unblinded AI reviewer. No independent human validation.

6

Trigger placement in REQ-018

Charging requires a request and successful connector locking.

StrategySaved When field
Zero-ShotThe system processes the charging request
StructuredA charging request is received.
Few-ShotA charging request is received and the connector is locked successfully.

Zero-Shot: 7/10. Structured and Few-Shot: 10/10.

The requirement does not impose a unique request/locking order.

7

Necessary conditions in REQ-023

Accept only if checksum is valid AND message age is less than 100 ms.

StrategySelected scenario and outcomeTotal
Zero-ShotValid checksum + young command: accepts6/10
Few-ShotValid checksum + young command: accepts6/10
StructuredValid checksum + age exactly 100 ms: rejects10/10

The manual reference also assumes guaranteed acceptance.

Necessary conditions do not, by themselves, guarantee acceptance.

8

Condition fidelity and unsupported additions

Condition/boundary score: 2/2 for all 90 cases.

This measures one scenario, not exhaustive branch coverage.

Material additions: both occur in REQ-023.

Minor setup restrictions and material logical inventions remain separate.

Interpretation and limitations

ComparisonHigher / equal / lower
Structured minus Zero-Shot4 / 26 / 0
Few-Shot minus Zero-Shot3 / 27 / 0
Structured minus Few-Shot1 / 29 / 0

Without REQ-023, Structured and Few-Shot tie at 10/10.

One unblinded AI reviewer. Synthetic data. One generation per pair.

No independent human validation, hardware execution or measured speedup.

11

Conclusion and next research steps

The prototype generates reviewable Given–When–Then drafts.

90 recorded outputs, shared scoring rules, analysis and a working local demo.

Clearer structure can coexist with logical and reference errors.

Next research: independent human review, repeated runs and broader requirements.
